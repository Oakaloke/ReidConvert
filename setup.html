Turn it on: accounts, limits & billing

Accounts, the free conversion limit, and $5/month Member billing are already built and tested — they ship switched off so the public site is unaffected. Work through the three phases in order. Full detail lives in docs/SUPABASE_SETUP.md and docs/STRIPE_SETUP.md.

Current state: everything below is gated behind flags in assets/js/config.js. Nothing charges anyone and no login UI appears until you complete Phase 1 and flip the flags.
1

Create accounts (Supabase)

≈ 15 minutes · required first

  1. Create a free project at supabase.com. From Settings → API, copy the Project URL and the anon public key (the anon key is safe to ship).
  2. Paste both into assets/js/config.js: 
    SUPABASE_URL: 'https://xxxx.supabase.co',
SUPABASE_ANON_KEY: 'eyJ...'
  3. In the Supabase SQL editor, paste & run the schema block from docs/SUPABASE_SETUP.md (creates profiles + row-level security, the sign-up trigger, conversion_history and its index).
  4. (Optional) Enable the Google provider under Authentication → Providers and add https://reidconvert.com/account/ to the redirect allow-list.
  5. Set AUTH_ENABLED: true in config.js, then commit & push.

Result: the header shows Log in, and sign-up, log-in, password reset and the /account/ page all work. Conversions start being counted per user.

2

Set the free conversion limit

≈ 1 minute

  1. The free allowance is one number in config.js — change it any time: 
    FREE_MONTHLY_CONVERSIONS: 10   // conversions per calendar month
  2. Usage is tracked as soon as accounts are on, but nobody is blocked until you set USAGE_ENFORCED: true. Leave it off until billing is live (Phase 3), so free users always have a way to upgrade.

Result: the /account/ page shows “X of 10 free conversions used this month.” When enforced, hitting the limit shows a clean Upgrade to Member prompt.

3

Switch on $5/month payments (Stripe)

≈ 30–45 minutes · needs a serverless host

  1. In Stripe → Products, add “ReidConvert Member” with a $5.00 USD / month recurring price. Copy the Price ID (price_…).
  2. Deploy the three functions in serverless/ (create-checkout-session, create-portal-session, stripe-webhook) to a host — Supabase Edge Functions, Netlify, Vercel or Cloudflare. Install stripe + @supabase/supabase-js.
  3. Set the host environment variables from .env.example (never commit these): 
    STRIPE_SECRET_KEY=sk_live_...        STRIPE_PRICE_ID=price_...
STRIPE_WEBHOOK_SECRET=whsec_...      SUPABASE_SERVICE_ROLE_KEY=...
SUPABASE_URL=...                     STRIPE_SUCCESS_URL / STRIPE_CANCEL_URL
  4. Register a Stripe webhook pointing at your deployed stripe-webhook URL; subscribe to checkout.session.completed, customer.subscription.updated, customer.subscription.deleted; copy the signing secret into STRIPE_WEBHOOK_SECRET. Make sure the host passes the raw request body.
  5. Point the site at your functions — set the base URL in config.js: 
    FUNCTIONS_URL: 'https://xxxx.supabase.co/functions/v1'
    The Pricing & Account “Upgrade” buttons light up automatically.
  6. Test in Stripe test mode: complete a checkout and confirm the webhook flips the user’s subscription_status to active.
  7. Finally, set MEMBERSHIP_ENFORCED: true — the one flag that starts enforcing Free vs Member limits.

The flags (in assets/js/config.js)

FlagDefaultWhat it does
AUTH_ENABLEDfalseShows login UI and turns on accounts. Needs the Supabase keys set.
FREE_MONTHLY_CONVERSIONS10The free monthly conversion allowance. Members are unlimited.
USAGE_ENFORCEDfalseActually blocks free users at the limit (with the upgrade prompt). Keep off until billing is live.
FUNCTIONS_URL''Base URL of the deployed Stripe functions. Empty → Upgrade buttons stay “coming soon.”
MEMBERSHIP_ENFORCEDfalseTreats paying users as Members (unlimited) and enforces Free limits. Flip last, after a test checkout works.

Before you go live — test

  • Sign up, log in, log out, and “forgot password” all work from /login/ and /signup/.
  • A test-mode Stripe checkout completes and the webhook sets subscription_status = 'active'.
  • Cancelling a subscription (customer.subscription.deleted) sets it back to free.
  • A free user is blocked after the limit; a Member converts without limits.
  • Row-level security holds: from the browser console a normal user cannot change their own subscription_status.

Mark a user as Member (for testing, before Stripe)

Run this in the Supabase SQL editor — it’s exactly what the Stripe webhook does automatically once billing is live:

update public.profiles
set subscription_status = 'active'
where id = (select id from auth.users where email = 'you@example.com');

Set it back to 'free' to test the Free experience again. (A Member is only treated as unlimited when MEMBERSHIP_ENFORCED: true.)
